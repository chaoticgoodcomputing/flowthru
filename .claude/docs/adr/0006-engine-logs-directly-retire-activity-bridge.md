# Engine internals log via `ILogger<TSelf>`; the `FlowthruActivityLogger` bridge is retired

`FlowthruService`, `ParallelFlowScheduler`, and other engine components take `ILogger<TSelf>` dependencies and emit human-readable lifecycle and validation logs directly, replacing the previous pattern where `FlowthruActivitySource` emitted `Activity` events and `FlowthruActivityLogger` (in `Flowthru.Cli`) bridged them into `ILogger.Log*` calls. `ActivitySource` emissions remain in place for distributed-tracing consumers — their actual purpose — but they are no longer the channel for human logs. The bridge existed only as a workaround for the constraint "core cannot depend on `ILogger`," which the step-logging convention ([ADR-0005](./0005-step-logging-via-shared-ilogger.md)) eliminates; keeping the bridge alongside direct logging would be a backwards-compatibility shim with no real consumer. Hosts that want logs suppressed register `NullLoggerFactory` — the standard .NET escape hatch — rather than relying on the absence of a logging bridge.
