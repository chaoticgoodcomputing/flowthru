# Tools as a development context

Flowthru introduces a `src/tools/` top-level directory and a Tool Developer context — paralleling Extension Developer and Core Developer in `/CONTRIBUTING.md` — to house artifacts that consume Flowthru from outside a Flow Dev's project: a long-running .NET Inspector that loads a Flow Dev's compiled assembly and exposes a shared introspection RPC, plus the polyglot frontends that consume that RPC (a TypeScript VSCode extension, an MCP server, future CLI surfaces). Tools differ from Extensions in two structural ways: (1) Tools are *processes* invoked from outside a Flow Dev's project, while Extensions are *libraries* a Flow Dev adds via NuGet; (2) Tools may be polyglot, while Extensions are .NET-only — the Inspector itself is .NET because it must load a Flow Dev's assembly, but frontends are free to be whatever language their host demands. The existing `Flowthru.Cli` under `src/core/` is a Tool-shaped artifact in the wrong place; future migration to `src/tools/` is plausible but non-blocking.
