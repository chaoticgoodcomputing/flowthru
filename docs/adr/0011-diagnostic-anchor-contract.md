# Diagnostic Anchor Contract

To enable Tool renderers — notably the planned VSCode Editor Frontend's "F2" surface, which projects Roslyn diagnostics onto a DAG canvas — Flowthru analyzers carry structured "anchor" metadata in `Diagnostic.Properties` that ties each diagnostic to the DAG element it concerns (a Step, Item, Edge, Flow, or Schema). Four decisions define the contract: (1) anchoring is **analyzer-side** with a small Core helper, not renderer-side projection — analyzers already know the DAG element when they emit a diagnostic, so re-deriving it via AST walking in every Tool is wasteful and creates a permanent Tool↔Core coupling running the wrong direction; (2) the schema is **composite** — a diagnostic carries whichever anchors it can resolve (Step.Label, Flow.Label, Item.Label, Edge.From/To, Step.Type fallback, or the explicit `Anchor.None` sentinel) and the renderer prioritizes label → edge → type-symbol → unanchored, so every analyzer can emit its strongest available identification without forcing label resolution where the analyzer can't see one; (3) keys are **numbered + flat** (`Flowthru.Anchor.Step.0.Label`, etc.) — always indexed even for single-anchor diagnostics, so readers never branch on single-vs-multi; (4) the analyzer-side seam is **a `FlowthruAnchor.Builder()` + a `CreateFlowthruDiagnostic` extension method on `SyntaxNode`/`Location`** — *not* a `FlowthruAnalyzer` base class. The base-class option was considered specifically for compile-time guarantee, but rejected: any caller can bypass a base by calling `Diagnostic.Create` directly, so the supposed guarantee doesn't actually hold; meanwhile a base class deviates from Roslyn's idiomatic pattern (its own `Roslyn.Diagnostics.Analyzers` and `PublicApiAnalyzers` use static extension methods on `SyntaxNode`/`SyntaxReference`, abstract bases only for C#/VB sharing). The real enforcement comes from test conventions (every Flowthru-namespace analyzer test asserts a parseable anchor block on every emitted diagnostic) and an optional later meta-analyzer that flags raw `Diagnostic.Create` calls inside `Flowthru.*` source. Retrofit of existing analyzers (FT1101, FT1102, Schema set, extension-shape set) is F2-priority-driven and incremental; new analyzers comply from day one.
