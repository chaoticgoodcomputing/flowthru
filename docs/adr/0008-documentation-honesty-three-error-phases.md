# Documentation honesty has three error phases

Flowthru's documentation tooling mirrors the three error phases defined in [`/CONTRIBUTING.md`](/CONTRIBUTING.md) — design-time, pre-flight, runtime — applied to the question *"can the docs lie?"* rather than *"can the Flow fail?"*. Design-time honesty (the gold standard) is enforced by docfx failing the build on broken `[!code-*]` includes and missing `#region docs:*` anchors, paired with a freshness test that fails on orphan regions or orphan include refs — same shape as `tests:_test:capability-matrix-freshness`. Pre-flight honesty is enforced by Starlight failing the build on broken internal markdown links, plus a non-blocking terminology lint that warns on uses of `_Avoid_:` terms drawn programmatically from per-context CONTRIBUTING.md glossaries. Runtime concerns — external link rot, output-content drift in tutorials beyond the "example exits 0" smoke test — are handled out-of-band by scheduled cron workflows that file issues rather than blocking PRs, because they're third-party reality changing rather than a Flowthru contract being violated. The deliberate non-symmetry with the framework's own phases is that documentation has no real "runtime" of its own; what we call runtime here is "the rest of the internet changed," and gating PRs on that would punish unrelated work for external rot.
