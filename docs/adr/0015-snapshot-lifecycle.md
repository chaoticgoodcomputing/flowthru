# Snapshot lifecycle: build-coupled refresh, `.flowthru/manifests/` location

The [[Inspector]]'s `dag/snapshot` endpoint reads a JSON manifest representing "what built last successfully" — the pre-flight checkpoint that F6 (built-last vs. now diff) compares against the live Roslyn view, and that surfaces preflight-class errors Roslyn alone can't catch. Three decisions define the lifecycle. **(1) Refresh is build-coupled with a manual override** — a Flowthru build target emits the snapshot as a build side-effect (so "built-last" honestly means built-last), and the Inspector's `flowthru/dryrun` RPC method serves the manual case (a Flow Dev mid-edit who wants to verify their in-progress refactor is preflight-clean). Editor-coupled triggers (on-save, on-idle) were rejected: they conflate "built-last" with "saved-last," undermining F6's semantic. **(2) The artifact lives at `.flowthru/manifests/<flow-label>.json`** — dot-dir convention matching `.git/`, `.vscode/`, `.idea/`, `.next/`, `.turbo/`; .NET-neutral by name (so Flowthru's Python or other extension paths don't make the location awkward); opens a future slot for other Flowthru-local state (cache manifests, logs, user prefs). The companion convention is one `.gitignore` line: `.flowthru/`. **(3) Format is whatever `JsonMetadataProvider` already emits** — the existing `DagMetadataProjection`. A merged dry-run (`RunAsync(flowLabel: null)`) naturally produces a single merged file because `EffectiveFlow == MergedFlow` in that case. File mtime serves as the v1 freshness signal (renderer shows "snapshot from X minutes ago"); richer meta (git SHA, project-state hash, Flowthru version) is deferred until F6 reveals demand.
